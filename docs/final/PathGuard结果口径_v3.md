# PathGuard 项目与评测口径（v3，当前唯一对外版本）\n\n更新日期：2026-09-23\n适用范围：产品前端、项目书、答辩材料和对外介绍。旧版本中与本文不一致的统计和表述均以本文为准。\n\n## 一句话定位\n\nPathGuard 是面向工程车辆规划、测试和项目交付团队的**离线候选轨迹验证优先级工作台**：在闭环仿真或实车验证之前，帮助工程师先找到值得复核的路线，解释数据证据和几何边界余量，并把人工、仿真或实车结论形成可追溯记录。它不是车载控制器、自动安全认证器，也不替代实车验证。\n\n参赛口径为“AI+产品”方向下的软件型研发验证工具。该方向的具体适配理由是产品服务工程机械研发/验证链路，并未宣称已成为“类人化智慧大小脑”或整机控制产品。\n\n## 更贴近工程师工作方式的批次代理分析\n\n冻结留出表没有规划器调用ID/候选批次ID，不能严谨恢复“一次任务里同时产生的候选路线”。因此对已确认五轴/六轴样本，使用 `map_id × vehicle_structure` 作为**代理比较上下文**，只纳入至少2条候选的4组。33条候选中有27条失败。各组选择预算为 `ceil(20%)`，并对截点同分按比例分摊：\n\n| 方法 | |\n\n解释边界：代理组可能仍合并不同规划运行；含单条样本的地图—车型组不参与；结构未定样本进入人工核验而不用于同车型排序；代理评测只有4组且组内失败比例很高，结论不稳定。当前结果**没有证明学习模型或规则优于同组随机基线**。下一轮冻结数据应记录稳定的 `planner_run_id / candidate_batch_id`、路线生成版本和场景配置，再开展真正的同批排序评测。\n\n可复算脚本：`scripts/audit_candidate_batch_metrics.py`；表格：`reports/final/tables/candidate_batch_proxy_metrics.csv`；摘要：`reports/final/candidate_batch_proxy_summary.json`。\n\n## 空间特征消融结论更正\n\n冻结集合中只有26条样本通过边界语义校验，全部为五轴。旧空间实验预测文件里，55维基线和“空间增广模型”逐行分数完全相同，并且按地图分组时预测在每组内恒定，说明旧输出不能证明空间特征“无收益”，也不能证明增广模型有效。旧报告的“无提升”结论撤回；该实验应标注为**实现/验证证据不充分，结果不用于模型优劣判断**。\n\n因此几何边界规则保留为可解释的独立筛查层，不接入训练模型，不宣称它改善了Top-K。重新实验的进入条件：补足按 `candidate_batch_id` 成组的标签；边界、车型配置在留出批次内完整可用；在未见地图/批次隔离的预先登记比较中与55维基线、公平固定几何规则、同预算随机基线对照；以失败PR-AUC、同预算失败捕获、批次级置信区间及严重失效捕获共同判定。样本和车辆结构覆盖不足时只报告“不确定”。\n\n## 产品流程和强制复核\n\n产品分开呈现三类证据：\n\n1. **学习模型失败风险**：55维特征、历史标签下的排序分数；不是物理碰撞概率。\n2. **固定工程应力规则**：用冻结开发集参考分布计算相对应力；与学习模型独立，不称作模型归因。\n3. **真实几何边界估算**：仅对通过语义检查的原始坐标启用，显示最小估算余量、左右侧、路线里程及条件化车辆参数。\n\n验证队列先纳入所有P0、结构未确认、模型—规则冲突和经可信边界局部估算发现越界的路线，再按常规风险分数补足Top-K。强制复核可能使实际展示数量超过Top-K；队列会标出预算外项和入队原因，不把它们静默挤出。低风险也不等于免检。\n\n验证回填采用本机SQLite持久保存，并记录样本ID、路线哈希、模型/特征版本、配置指纹、当时的排序/几何证据、验证方式、验证结果和工程备注。它是本机工作流能力，不是云端多人协作或自动在线再训练。\n\n##
