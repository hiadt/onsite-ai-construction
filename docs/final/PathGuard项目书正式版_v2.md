# PathGuard——工程车辆候选轨迹可信风险评测与验证决策系统

## 一、项目摘要

在工程机械施工场景中，一台车辆往往会产生大量候选轨迹。将所有候选轨迹逐条送入闭环仿真、人工复核和实车测试，会消耗大量计算、测试和工程师时间；而只依靠单一阈值，又难以解释复杂弯道、坡道、窄道和速度变化造成的风险。

PathGuard位于候选轨迹生成与后续仿真/实车验证之间。系统读取候选路线和车辆结构信息，提取55维工程特征，以学习模型生成失败风险主排序，同时使用几何应力规则进行独立交叉校验，最终输出风险原因、证据状态和Top-K验证优先级；当模型与规则明显不一致时，系统转入人工复核，而不是自动放行。

PathGuard的目标不是自动控制车辆，也不是替代实车检测，而是帮助工程师回答两个问题：

1. 在有限验证预算下，哪几条候选路线应该先验证；
2. 这条路线为什么需要优先复核，以及下一步应该做什么。

## 二、工程痛点

### 1. 候选路线多，验证资源有限

规划器生成的路线数量通常大于人工、仿真和实车能够逐条验证的数量。平均分配验证资源会造成大量低价值重复验证，也可能遗漏真正需要优先检查的失败路线。

### 2. 风险由多因素共同造成

曲率变化、速度—曲率耦合、横向加速度代理、转向变化、横摆动态、坡度和边界净空可能共同影响路线可执行性。单一阈值无法表达这些因素的组合效应。

### 3. 车辆结构和证据状态并不总是完整

工程数据中可能同时存在五轴、六轴和结构未定样本。对于结构未定、字段缺失或超出历史覆盖范围的样本，系统需要保留不确定性并建议人工复核，而不是强行输出确定性结论。

## 三、产品定位

PathGuard是一套面向工程车辆候选轨迹的离线风险排序与验证决策产品。

```text
候选路线与车辆结构
        ↓
55维工程特征检查
        ↓
学习模型主排序 + 几何应力规则交叉校验
        ↓
风险等级、原因解释和证据状态
        ↓
Top-K验证队列
        ↓
仿真、人工复核或实车测试
        ↓
结果回流与后续校准
```

每条候选路线至少输出：

- 学习模型风险；
- 几何规则风险；
- 综合验证优先级；
- 风险等级；
- 五轴、六轴或结构未定标签；
- 主要风险因素；
- 证据状态；
- 下一步动作建议。

## 四、技术方案

### 1. 特征层

当前特征契约包含55个固定字段，覆盖：

- 路线曲率和曲率变化；
- 速度与曲率耦合；
- 横向加速度代理；
- 转向幅值和变化；
- 横摆角速度及变化；
- 坡度；
- 静态边界净空；
- 局部窗口统计；
- 路线长度、点数和结构证据等元数据。

特征版本为 `pathguard_preexec_v2.0.0`，Schema使用固定SHA-256校验，避免训练和演示过程中字段错位。

### 2. 模型层

当前Gate3模型采用HistGradientBoosting作为主要学习模型。模型使用冻结的监督样本训练，并按地图分组进行开发、测试和重复审计，避免同一地图的高度相似路线同时出现在训练和测试中。

### 3. 规则层

规则层独立计算几何应力风险，重点检查曲率、速度—曲率耦合、横向加速度代理、转向、横摆、坡度和静态净空。规则不直接替代学习模型，而是用于：

- 解释风险来源；
- 提示工程底线风险；
- 检查学习模型与工程常识是否明显不一致；
- 触发人工复核。

### 4. 可信拒判层

出现以下情况时，系统不静默给出确定性结论：

- 车辆结构未定；
- 必要字段缺失；
- 特征出现非有限值；
- 样本明显超出当前数据覆盖范围；
- 学习模型与规则风险严重不一致。

此时系统输出“结构未定”或“证据不足”，并将路线转入人工复核或补测队列。

## 六、验证结果

### 1. 独立地图测试

独立测试集包含5张未参与开发的地图，共66条样本，其中39条为失败样本。

| 指标 | 结果 |
|---|---:|
| ROC-AUC | 0.6149 |
| PR-AUC | 0.6994 |
| 失败召回率（开发集选择阈值） | 0.9744 |
| 失败精确率 | 0.6129 |
| F1 | 0.7525 |

独立测试中，风险排序前10、20、34条分别捕获约20.5%、43.6%、61.5%的失败样本，均高于同等预算下的随机选择期望。

### 2. 全量OOF和重复地图审计

全量OOF结果的失败PR-AUC为0.7274。60次地图分组重复审计显示：

- 纯规则平均失败PR-AUC约0.6917；
- 50%模型+50%规则平均失败PR-AUC约0.7257；
- 纯模型平均失败PR-AUC约0.7275；
- 50%模型+50%规则的平均ROC-AUC约0.6679（作为离线审计对照，不作为产品固定权重）；
- 50%模型+50%规则的Top-10、Top-20、Top-34平均失败捕获率约为22.0%、43.0%、65.4%。

因此，产品展示中将学习模型作为主要排序依据，把规则作为独立工程校验和解释层，不宣称某一固定混合权重已经在所有指标上最优。

### 3. 结构子群结果

六轴样本的OOF PR-AUC约0.8274，五轴样本约0.5932，结构未定样本约0.7706。五轴样本表现相对较弱，说明后续需要开展五轴专项校准、失效案例补标和场景覆盖扩展。

该结果不会被隐藏，而是转化为产品动作：五轴高风险路线提高人工复核优先级，结构未定样本保留拒判状态。

## 七、产品创新点

### 1. 从“预测是否失败”转向“决定先验证什么”

产品输出面向验证资源分配，而不是只输出一个分类标签。Top-K队列直接对应工程师下一步要检查的路线。

### 2. 工程特征与AI模型结合

模型输入保留曲率、速度、转向、横摆、坡度和净空等工程含义，风险结果可以回溯到具体因素，便于工程师复核。

### 3. 学习模型与规则独立校验

学习模型用于风险排序，规则用于工程解释和底线检查。两者不一致时提高人工复核优先级，避免把AI输出直接当成安全结论。

### 4. 证据不足时可信拒判

结构未定、字段缺失和超出覆盖范围的样本不被强行归类，系统明确告诉工程师还需要什么信息或验证动作。

## 八、客户共创与拟开展试点

当前客户共创内容为拟开展方案，不将尚未发生的访谈、部署或成本节省写成既成事实。

### 场景一：狭窄通道和边界净空

客户提供候选路线、车辆结构和边界信息。PathGuard筛选静态净空和局部几何风险较高的路线，生成优先人工复核和补测队列。工程师确认边界风险后决定是否进入闭环仿真或实车测试。

### 场景二：坡道、弯道和速度—曲率耦合

系统关注坡度、速度—曲率耦合、曲率变化和横向加速度代理，帮助工程师优先检查可能出现组合风险的候选路线。试点验收重点是风险原因是否可解释、Top-K队列是否能减少低价值路线进入后续验证。

### 场景三：五轴和六轴路线批量筛选

客户将不同轴数车辆的候选路线统一导入，系统分别展示结构筛选、模型风险和规则风险。结构未定样本进入人工复核，不参与未经说明的车型确定性结论。

## 九、产品演示

统一使用Streamlit入口：

```bash
streamlit run demo/app.py
```

演示流程：

1. 打开产品总览，展示数据口径和模型状态；
2. 选择五轴、六轴或结构未定；
3. 进入风险队列，按风险等级和地图筛选；
4. 打开一条高风险路线；
5. 查看模型风险、规则风险、风险原因和证据状态；
6. 生成Top-K优先验证队列；
7. 展示下一步动作：人工复核、优先补测或客户共创确认。

## 十、产业化路径

### 阶段一：离线评估工具

以CSV或标准接口读取候选轨迹特征，输出风险队列和验证报告。

### 阶段二：客户小规模试点

接入客户新地图、新配置和已有复核流程，验证跨地图稳定性、解释有效性和人工复核工作量变化。

### 阶段三：工程系统集成

与候选轨迹生成器、仿真管理工具和测试结果管理系统对接，形成版本化风险评估和结果回流服务。

## 十一、边界与后续计划

- 当前结论来自离线历史数据，不等价于实车安全验证；
- 高风险表示应优先复核，不表示路线一定失败；
- 低风险表示相对低风险，不表示可以跳过实车测试；
- 结构未定样本不强行推断车型；
- 当前尚无真实客户现场部署结果，客户共创部分为拟开展方案；
- 下一阶段重点是五轴专项校准、新地图验证、真实客户访谈和结果回流。

## 十二、参赛核心价值

PathGuard把工程车辆候选轨迹从“逐条平均验证”转化为“按风险优先验证”。它的核心竞争力不是声称替代现有安全流程，而是把工程特征、AI排序、规则解释、证据等级和下一步动作组合成一个可以在实际研发流程中使用的决策工具。
