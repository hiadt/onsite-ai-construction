# PathGuard 任务化评估与验证闭环修改报告

日期：2026-09-23  
工作分支：`codex/task-workflow-validation`，基于 `codex/p0p1-demo-handoff` 的 `e262117`。  
定位：工程车辆候选轨迹可信风险评测与决策系统。

## 本轮解决的问题

此前工作台直接列出历史样本编号。一个编号对应一份来源路线记录，但页面没有清楚交代任务、场景、输入文件覆盖范围和局部动画之间的关系；来自不同来源的记录也容易被误解为同批候选。验证反馈可以保存在本机，但缺少环境与路线版本、有效车辆配置、多次结论争议和训练资格审核。

本轮将客户操作组织为“建立工程任务 → 导入同条件候选 → 风险排序与全路线定位 → 局部空间分析 → 分别登记验证 → 审核并导出证据”。历史案例库与新任务在工作台中分开。学习模型、固定工程规则和车辆尺寸边界计算保持独立口径。

## 已实现

| 模块 | 交付行为 | 主要文件 |
| --- | --- | --- |
| 任务入口 | 历史案例库、新建评估任务、已保存任务；新建任务记录名称、场景、环境版本和“待评估/已有验证记录”输入状态。新任务必须上传至少一份 NPZ，先通过冻结特征提取校验。 | `demo/app.py`, `demo/task_store.py` |
| 输入追溯 | 按 SHA-256 存原始路线、配置、特征/模型版本及评估快照；同任务候选使用提交的同一场景与车辆配置。任务 ZIP 可导出原件、评估快照、附件和反馈。 | `demo/task_store.py` |
| 路线解释 | 队列优先显示候选路线名、输入长度和场景，保留编号用于追溯；详情显示完整输入路线，并用橙色标出局部动画前后约 35 米的区段。明确工程关注点属于同一输入路线。 | `demo/app.py` |
| 车辆配置比较 | 车辆长宽、参考点调整后，比较上传基准与当前配置的最小边界余量、最小点里程及沿程余量曲线。仅在已确认尺寸且边界筛查通过时给出结论。 | `demo/route_input.py` |
| 验证时间线 | 分别记录人工、闭环仿真、实车/现场或其他平台的结果；附严重程度、环境/路线版本、条件一致性、证据完整性、报告附件、复核状态。可信度按“条件/核对/可复查证据”分层显示，不赋予任意百分比。有效滑块尺寸进入反馈，不再只保存原始配置。 | `demo/feedback_store.py`, `demo/app.py` |
| 争议处理 | 同一路线、同环境和路线版本、同车辆有效配置下，互相矛盾的通过/失败结果标为争议；已批准的训练候选资格自动撤回。模型低风险而验证失败提示优先排查。不同条件下的结果分别保留。 | `demo/feedback_store.py` |
| 数据审核 | 新反馈默认“待审核”；只有条件一致、结果明确、已核对且无同条件矛盾时，可人工标为“可用于训练候选”。可导出候选 CSV，不触发自动重训。 | `demo/feedback_store.py`, `demo/app.py` |
| 本任务 Top-K | 同任务有至少 5 条可比较且已核对的候选、至少 2 条失败及 1 条通过时，描述性比较学习模型、固定规则和同名额随机期望，并统计严重失败漏掉数；条件不足显示原因。 | `demo/batch_evaluation.py` |

## 使用路径

1. 打开首页，进入“风险工作台”，展开顶部“任务与输入”。
2. 查看历史案例时，选择“历史案例库”。这些案例用于回顾来源记录，不自动组成一次规划任务的候选批次。
3. 做新的工程评估时，选择“新建评估任务”，填写任务与场景版本，上传同条件候选 NPZ 和车辆配置 JSON，点击“保存任务并评估”。已有验证结果可在后续路线详情逐次录入。
4. 在“候选路线”按路线名与长度查看排序；在“路线分析”先看完整输入路线，再看局部动画、数值、基准/调整尺寸比较与验证记录。
5. 验证后填写测试方式、结果和条件，按需要上传报告或日志。出现冲突时复核版本、场景和实际配置；审核后导出训练候选或整项任务证据包。

## 当前能力边界与下一步数据要求

目前新任务的直接原始输入格式是现有特征契约支持的路线 NPZ 与车辆配置 JSON；任意仿真工程项目文件、地图包和实车原始日志尚未做通用解析。验证附件可以作为证据保存，不能仅凭附件自动产生训练标签。

车长与车宽改变的是给定轨迹上的刚性外廓及可信边界局部余量。现有 55 维学习模型不以可调尺寸为输入，也不会因滑块变化而重算风险分。冻结样本中通过完整边界点列筛查的仅 3 条五轴路线，六轴尺寸联动仍缺乏合格边界数据。新尺寸能否实际跟随原轨迹，还需要规划或闭环仿真验证。

历史留出成绩与新任务 Top-K 面板分开。此前同任务代理分析没有证明排序优于随机；新面板只在出现足够的同任务已核对结果后显示描述性对比。跨地图泛化、严重失效漏检和候选多样性，需要后续真实批次持续采集，并按地图/任务严格隔离训练和测试。

训练候选导出仍须经过独立的去重、标签审查、地图/任务分组隔离、重训和留出验证。本轮没有把新反馈自动并入既有冻结模型。历史项目书及其原始实验指标未因界面迭代而更改。
