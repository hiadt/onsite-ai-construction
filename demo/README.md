# PathGuard 一体化产品演示

PathGuard 是工程车辆候选轨迹的离线风险排序与验证安排原型。首页以完整主视觉和客户价值开场；产品介绍再讲使用场景、三步工作流和交付结果；风险工作台提供体验历史路线、新建评估任务和已保存任务三个入口。日常操作先看建议与位置，专业指标和技术依据按需展开。系统不直接控制车辆，不构成安全认证。

新建任务必须填写任务、场景和环境版本，并上传候选NPZ。系统先按冻结特征契约验证文件，再把原始路线、配置、文件哈希和评估快照保存在本机 `LocalAppData/PathGuard/tasks/<task_id>/`。同一任务的候选可以比较；历史案例库中的不同编号不自动组成候选批次。路线详情使用可读路线名和长度，追溯编号仅供查源。全路线图标出动态局部约70米区段，关注点仍属于同一条输入路线。

验证可以多次追加：人工复核、闭环仿真、实车/现场测试或其他测试平台各自记录结果、严重程度、验证环境和路线版本、车辆有效尺寸、证据完整性、条件一致性及复核状态。若同条件验证结论相反，系统标记争议并撤回既有训练候选资格；模型低风险而验证失败会优先提示排查。新记录默认待审核，只有条件一致、结论明确、已核对且无同条件矛盾时才可人工设为训练候选。导出的任务ZIP包含原始路线、配置清单、评估快照、附件和验证记录；模型不会因记录提交而自动更新。

“专业依据”的技术附录还会对本任务已核对、同条件的候选计算描述性Top-K：学习模型与固定工程规则在相同名额下找到多少失败、漏掉多少严重失败，并显示随机期望。少于5条有效候选、少于2条失败或没有通过样本时只显示样本不足。结果不自动替代跨地图验证；现有历史样本没有真实的同任务候选批次ID，因此仍以历史留出实验单独展示。

统一结果与统计口径见 `docs/final/PathGuard结果口径_v3.md`；同步后的项目书源稿见 `docs/final/PathGuard项目书正式版_v3.md`。历史交付说明仅记录当时版本，其中的边界覆盖和空间消融结论可能已由 v3 复核修订。

网站一级导航为“首页—产品介绍—风险工作台”。风险工作台内部为“浏览导览/任务概览—历史路线/验证顺序—路线详情—专业依据”。路线清单用稳定的可读名称区分同场景的不同记录，不在主表显示哈希追溯号；原始编号和路线来源可在路线详情的技术折叠区查阅。全程与局部图并排展示、保持米制比例，关闭拖动与滚轮交互；专业图改为显式的关注点选择和放大开关。网页文件选择器、主要操作与图表提示均以中文呈现。

比赛展示时，历史入口默认展示 **340 条冻结监督记录**，也可切换其中 **15 条快速讲解示例**。最初的12条来自 Gate 3 前端交付包，覆盖五轴、六轴、结构未定和通过/失败；后续加入3条通过边界完整性筛查的五轴路线。这不是预先登记的代表性抽样；15条的复核比例不代表日常工程比例。现已从本机哈希匹配的原始NPZ逐条重提并核对55项特征，生成全部340条路线坐标演示资产 `demo/data/route_geometry_all.json.gz`；生成脚本为 `scripts/build_full_route_geometry.py`。资产不含原始文件、本机路径或用户凭据。全部记录可展示原始路线、局部关注点和条件性车身扫掠，但仅3条通过边界完整性筛查，其他记录不能声称具有可信的道路边界或尺寸联动碰撞结论。部署模型在340条记录上重训，全集评分只供工作流查看，不能作为独立泛化成绩。新建任务入口才展示同一任务的完整输入路线、本轮验证队列和其余按计划验证路线；只有一条路线时，系统提示无法衡量批次排序收益。页面不会把低优先级描述为免检。

路线详情先显示建议动作与动态车身示意，再用并排图说明当前路段位于输入全程的哪里；专业指标、尺寸设置和原始编号默认折叠。页面可调车长、车宽、路线参考点和人工复核余量，使用逐点位置与航向角重算米制刚性矩形外廓和四角扫掠轨迹。全量边界复核中，仅3条五轴路线同时通过距离、方向/次序和保守点列连续性筛查。历史示例的尺寸被标为假设值：用户可开启条件性余量试算以理解尺寸敏感性，但该结果不进入正式任务的预算外核查队列，也不被登记为真实车型配置。车长、车宽和参考点不进入现有55维学习模型，也不改写模型风险。

支持直接上传原始NPZ并自动提取55维特征，顶部任务输入区提供路线和车辆配置JSON示例。示例尺寸明确标为假设值，不代表真实车型参数。配置可声明vehicle_structure（five_axis/six_axis/unknown）、map_id、length_m、width_m和reference_from_rear_m；后三项用于几何扫掠，并在操作者确认及边界证据完整筛查通过时参与局部边界余量估算。内置模型是在全部340条样本上重训的部署模型，验证指标取历史留出预测，内置样本评分不能用来证明泛化性能。

几何规则采用274条开发样本的固定经验分布，不再根据上传批次计算百分位；规则工程提示不等于模型归因。当前工程基线结果见data/engineering_comparison.csv。历史60次审计使用旧规则，不作为新规则的重复验证成绩。

## 安装与启动

Gate 3模型由 `scikit-learn 1.0.2` 固化，建议使用 Python 3.10 创建独立环境：

```powershell
py -3.10 -m venv .venv-demo
.\.venv-demo\Scripts\python.exe -m pip install -r demo\requirements.txt
.\.venv-demo\Scripts\python.exe -m streamlit run demo\app.py
```

产品入口只有：

```bash
streamlit run demo/app.py
```

## 输入格式

历史案例库默认输入为 `demo/data/sample_input.csv`。新建任务使用NPZ和车辆配置JSON。历史入口上传CSV必须包含 `demo/data/feature_contract_v2.json` 中按顺序定义的全部55项 `training_feature_columns`，并满足：

- 所有训练特征都能转换为有限数值；
- 不缺列，不静默填充数值特征；
- 如提供 `feature_version` 或 `schema_sha256`，必须与冻结契约一致；
- `sample_id`、`map_id`、`route_id`、`vehicle_structure` 和标签状态仅作元数据显示，不进入模型矩阵。

冻结契约：

- 特征版本：`pathguard_preexec_v2.0.0`
- 训练特征：55项
- 局部窗口：10米
- 标签定义：`1=pass, 0=fail`
- Schema SHA-256：`b365d5b00779cc9f1e2858e695f0063112d94771a2cbc611c734d1110983d334`

## 真实模型与风险计算

模型路径：

```text
demo/models/pathguard_gate3_model.joblib
```

启动时会同时校验：模型可反序列化、`predict_proba`接口、55维输入、模型记录的特征名称与顺序、特征版本和Schema哈希。失败标签固定为0，学习模型风险取失败类别概率。

模型加载失败时，页面明确显示“学习模型未加载，当前为规则预览”，不会把规则分数伪装成模型结果。

几何规则只使用冻结55维中的曲率、速度—曲率耦合、横向加速度代理、转向、横摆率、坡度、静态边界净空和10米局部窗口指标。验证队列主排序使用学习模型失败风险，几何规则风险独立作为工程交叉校验：

```text
queue_score = 学习模型失败风险
rule_check = 几何规则风险
模型与规则分别展示；分数未同尺度校准，不用数值差触发人工复核
verified_boundary_rule = 尺寸联动的局部边界硬规则
```

风险等级为：高风险 `>=0.70`，中风险 `[0.45,0.70)`，低风险 `<0.45`；结构未定显示为“证据不足”。

边界估算先要求左右边界坐标复现净空数组（误差不超过 `1e-5 m`），再做路线法向左右方向、交叉次序、里程严格递增和边界点列连续性筛查。冻结340条中，340条均可读取，69条包含完整左右边界，26条通过距离语义校验，但只有3条进一步通过完整筛查；新增审计表为 `reports/final/tables/boundary_integrity_reaudit.csv`。其余样本继续显示模型与固定规则结果，并提示不能计算尺寸联动结论。完整筛查不证明走廊无自交，也不替代连续碰撞检测。

空间特征实验仅有26条通过距离语义校验的样本，且全部为五轴，其中3条通过更严格点列筛查；旧预测文件中基线和增广模型分数逐行完全相同、同地图内预测恒定，无法支持有效模型比较。旧报告“空间特征无提升”结论已撤回；几何特征不并入训练模型。恢复实验前须修复对照实现、建立真实 candidate_batch_id 并按地图/批次隔离，至少覆盖两类结构；候选进入条件为失败PR-AUC提升超过0.02且Top-10捕获不下降，同时报告批次级区间和严重失效捕获。当前样本远低于建模条件。

风险队列按模型分数给出有限名额的优先验证路线；车型资料待补和经完整边界筛查后的外廓估算越界项在名额外单列处理，并显示原因。P0表示优先安排闭环仿真验证，并不等于必须逐条人工先审。验证结果保存于运行电脑的 `LocalAppData/PathGuard/validation_history.sqlite3`；旧数据库自动增列迁移。历史记录包含路线哈希、模型/特征版本、有效车辆配置、验证条件、当时判断和逐次提交的结果，不回写冻结训练标签。导出的“训练候选记录”仍须在独立重训流程中做去重、分组隔离和性能验证。

## 验证依据

页面从以下仓库文件动态读取结果，不在前端手工写入指标：

- `gate3_test_metrics.json`：独立地图测试；
- `gate3_oof_metrics.json`：全量地图分组OOF；
- `repeated_group_hybrid_summary.json`：60次规则/模型地图分组审计；
- `failure_mechanism_cards.json`：独立测试失效机理证据卡；
- `freeze_data_card.json`：冻结数据口径。

所有指标均为离线地图分组验证结果，不是实车验证结果。PathGuard只用于安排候选路线验证优先级，不能代替闭环仿真、人工复核或实车验证。
