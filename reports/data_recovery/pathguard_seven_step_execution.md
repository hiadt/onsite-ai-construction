# PathGuard 七点执行说明

## 本次直接落地的内容

1. **统一去重入口**：新增 `scripts/data_audit/execute_seven_steps.py`，按路线文件 SHA、路线输入哈希、样本键和路径逐级生成唯一键，重复记录只保留证据等级更高的一条。
2. **四层数据集**：脚本输出真实标签、指标无最终标签、只有路线信息、只有汇总证据四个 CSV，避免把不同用途的数据混在一起。
3. **五轴/六轴统计**：脚本按车辆结构证据和控制向量维度识别五轴、六轴、未知，统计结果写入 `summary.json`。
4. **首版风险评分**：用滑移率、轮胎利用率、动态间隙、横向误差、航向误差做首版风险分数；只有路线信息的行会标注 `risk_source=proxy`。
5. **风险队列**：所有样本输出 `risk_scored_all.csv`，可直接按高、中、低风险筛选路线。
6. **弱标签分开保存**：`weak_labels.csv` 只保存有指标证据且风险较高/中等的候选，绝不覆盖真实通过/失败标签。
7. **展示原型**：新增 `demo/pathguard_demo.html`，用于比赛展示“路线输入—风险排序—补测/共创动作”的产品闭环。

## 目前已经确认的事实

- SHANYU000 回查的 3061 条路线：206 条有指标但没有最终标签，2855 条没有找到可靠结果。
- ZYJisBoss 回查的 32 条新增路线：没有新增可安全恢复的通过/失败标签；12 条只有汇总证据，1 条只有指标，28 条没有结果。
- 因此新增池目前不能宣称新增真实标签训练样本。真实标签仍只使用仓库中已有的明确结果。
- 五轴和六轴可以同时进入统一产品流程，但在统计和展示中保留结构字段，避免把两种车辆的阈值和样本混成一个黑箱。
- 风险分数、弱标签、路线代理排序都是研发/展示结果，不是实车最终判定。

## 在队友电脑上运行

在完整仓库根目录执行：

```bash
python scripts/data_audit/execute_seven_steps.py
```

输出目录：

```
data/derived/pathguard_v2/
```

先查看：

- `summary.json`
- `real_labeled.csv`
- `metric_only.csv`
- `route_only.csv`
- `aggregate_only.csv`
- `risk_scored_all.csv`
- `weak_labels.csv`

## 比赛展示主线

产品不说“替代实车检测”，而是说：PathGuard 在仿真和测试之前，把候选路线按风险排序，并解释风险来自哪里，再把高风险路线交给工程师和客户做重点复核。这样可以直接利用现有五轴、六轴路线和指标，同时把后续客户共创落到可执行的“补测—回查—阈值校准”闭环。
